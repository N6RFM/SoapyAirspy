* Soapy SDR plugin for Airspy R2 and Mini

This is a fork of [[https://github.com/ast/SoapyAirspy][ast/SoapyAirspy]] (the =v2= rewrite, itself
based on [[https://github.com/pothosware/SoapyAirspy][pothosware/SoapyAirspy]]), with fixes for bias tee, buffer
overflow handling, and buffer sizing. All credit for the original
driver and the =v2= mmap ring-buffer rewrite goes to those projects;
see [[#credits][Credits]] below.

Part of a set of three related repos, built together:
- [[https://github.com/N6RFM/gr-osmocom_n6rfm][gr-osmocom_n6rfm]] -- GNU Radio/GRC-level controls (Bias Tee
  checkbox, Gain Table dropdown) and =rx_overflow= stream tag
  emission, built on top of the fixes in this repo
- [[https://github.com/N6RFM/gr-overflow-monitor][gr-overflow-monitor]] -- a real, installable GRC block that reads
  those =rx_overflow= tags and logs pass reliability data

** Building

Make sure you have SoapySDR installed and do something like this:

#+begin_src bash
    mkdir build
    cd build
    cmake ..
    make
    sudo make install
#+end_src

** Using

*** Construction arguments (driver=, serial=)

These select and open a specific device -- consumed once, before the
device even exists yet, so they never show up in
=SoapySDRUtil --probe='s "Other Settings" list (that list is only for
the runtime settings covered below).

- =driver=airspy= - required, tells SoapySDR to use this driver
- =serial=<hex>= - selects a specific physical unit by serial number,
  e.g. =serial=744c60c8218e3e4f=. *Required if you have more than one
  Airspy connected* -- without it, SoapySDR's =Device::make()=
  silently opens whichever matching device happens to enumerate
  first (typically USB bus order, not something this driver -- or
  SoapySDR itself -- guarantees stays the same across reboots or
  reconnects). With only one Airspy connected, =serial== is optional.
  Find your device's serial with:
  #+begin_src bash
  SoapySDRUtil --find="driver=airspy"
  #+end_src
  Either hex format works identically --
  =serial=744c60c8218e3e4f= and =serial=0x744c60c8218e3e4f= parse to
  the same value (=std::stoull(..., 16)= optionally accepts a leading
  =0x= when the base is 16). =SoapySDRUtil --find= prints the
  no-prefix form, so that's the simplest to copy-paste directly.

Use this device string in GQRX:

#+begin_src
  soapy=0,driver=airspy
#+end_src

More settings are available:

#+begin_src
    soapy=0,driver=airspy,biastee=true|false,gains=linearity|sensitivity|manual,bitpack=true|false,bufsize=<bytes>
#+end_src

- =biastee= - enable the 4.5V bias tee (see [[#fixes-in-this-fork][Fixes in this fork]] below for
  why this didn't reliably work upstream)
- =gains= - gain mode: =linearity=, =sensitivity=, or =manual=
- =bitpack= - pack 4 12-bit samples into 3 16-bit words (25% less USB traffic)
- =bufsize= - ring buffer capacity in bytes, must be a power of two
  (default 4194304 / 4MiB). Increase this if you see overflows under
  host-side scheduling jitter; see the stats below to tell whether it's
  needed.

Runtime stats are exposed as read-only settings (readable via
=SoapySDRUtil --probe=, or =SoapySDR::Device::readSetting()=):

- =overflow_count= - number of ring buffer write timeouts (dropped
  sample blocks) since stream start or last reset
- =high_watermark= - largest number of queued bytes ever observed in
  the ring buffer
- =ringbuffer_capacity= - current ring buffer capacity in bytes

Write =reset_stats= (any value) to zero the counters above.

(=soapy=0= in the examples above isn't a SoapySDR or SoapyAirspy
concept at all -- it's specific to whatever application you're using
this with. See e.g.
[[https://github.com/N6RFM/gr-osmocom_n6rfm#device-arguments-explained][gr-osmocom_n6rfm's README]]
for what it actually does there.)

** Fixes in this fork
:PROPERTIES:
:CUSTOM_ID: fixes-in-this-fork
:END:

*** Bias tee not reliably turning on (the main fix)

Upstream, bias tee (and =bitpack=) were only ever asserted once, in
the device constructor, immediately after opening the device -- before
the caller (GQRX, GNU Radio, etc.) sets a sample rate or activates the
stream. In practice this meant the setting could be silently lost by
the time streaming actually started, and behavior ended up depending
on whatever another application had last left the hardware state as
(e.g. toggling bias tee on in SDR++ would "stick" independently of
what any SoapySDR-based app requested).

[[https://github.com/AlexandreRouma/SDRPlusPlus][SDR++'s]] native Airspy driver does not have this problem, because it
re-asserts =airspy_set_rf_bias()= every time streaming starts, *after*
setting the sample rate, immediately before =airspy_start_rx()=. This
fork adopts the same ordering: =activateStream()= now re-applies both
bias tee and bit-packing right before starting RX, every time. Each
application now reliably gets the state it asked for, rather than
inheriting whatever a previous session left behind.

*** Device-args string not applying settings

The constructor never applied =biastee=/=bitpack=/=gains= from the
device-args string (e.g. =soapy=0,driver=airspy,biastee=true=) --
that code was present but commented out. This is now re-enabled; it's
safe because =SoapyAirspy= has no subclasses, so the virtual
=writeSetting()= call always dispatches correctly.

*** Uninitialized members

=serial_=, the gain-stage fields, and =agcMode_= were left
uninitialized in the constructor when opened without a =serial=
device arg, which could return garbage from =getHardwareInfo()=/
=getGain()= before anything set them explicitly.

*** Silent sample drops / no overflow signaling

The ring buffer would silently drop a block of samples on write
timeout, logging at INFO level only -- =readStream()= never returned
=SOAPY_SDR_OVERFLOW=, so callers had no way to detect drops. This now
matches upstream =pothosware/SoapyAirspy='s behavior: an overflow sets
a flag that =readStream()= reports on the next call.

This is the signal [[https://github.com/N6RFM/gr-osmocom_n6rfm][gr-osmocom_n6rfm]] builds on: its patched
=soapy_source_c= turns each =SOAPY_SDR_OVERFLOW= into a
=rx_overflow= GNU Radio stream tag at the exact sample offset, which
[[https://github.com/N6RFM/gr-overflow-monitor][gr-overflow-monitor]]'s =Overflow Tag Monitor= block reads and logs.
=get_overflow_count()= also exposes a running total to Python
directly. None of this has anything to report against the unpatched
upstream driver.

*** Fixed 4MB ring buffer size

Ring buffer capacity is now configurable via the =bufsize= device arg
instead of a hardcoded =1 << 22=, with =overflow_count=/
=high_watermark= exposed so you can actually tell whether increasing
it helps for your workload rather than guessing.
